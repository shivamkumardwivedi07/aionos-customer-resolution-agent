## 2. Methodology & Prompt Engineering Strategy

### 2.1 Principle of Bounded Delegation
AI tools were strictly used as pair-programming accelerators and architectural verifiers. Crucially, the code generated by the AI was designed to prevent the AI itself from making arbitrary decisions at runtime:
* **The Architecture Inversion**: Rather than prompting an LLM with instructions like *"Decide if Arvind should get a hotel"*, the engineering prompt directed the AI to write **deterministic Python code** where `if delay_hours <= 5: hotel_eligible = False`.
* This ensures that no prompt drift or stochastic sampling can cause runtime hallucinations during an actual customer conversation.

### 2.2 Test-Driven Verification
All policy boundaries were codified into `pytest` test suites first, ensuring that any logic generated by the AI tools was empirically proven before declaring completion.
* **27 Passing Automated Tests**: Covering normal flows, boundary thresholds, adversarial attempts, and REST endpoints.
